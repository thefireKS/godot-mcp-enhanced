# qa

> QA test suite orchestration: structured test spec → auto-install the bridge → run the game → execute step by step → aggregated report + regression diff. Step types: input/wait/wait_frames/freeze/unfreeze/step_until/snapshot/restore/set/call/ watch_start|stop/monitor_start|stop/assert/screenshot/sleep; the 8 assertion kinds and each field's meaning are in the schema field descriptions. run supports mode:async for background runs (managed with qa status/cancel). Reports go to ~/.godot-mcp/qa-reports/<run_id>.{json,md}.

## Parameters

| Parameter | Type | Required | Description |
|------|------|------|------|
| `action` | enum (5 values) | ✓ | run = run a suite; report = read a report; diff = compare two reports for regressions; status = run registry (progress/final state); cancel = cancel a run in progress |
| `mode` | enum: sync | async |  | run: sync = wait for the full result; async = return run_id immediately and run in the background (poll with qa status, cancel with qa cancel). Default when unspecified: async if the client declares the MCP tasks capability, otherwise sync |
| `run_id` | string |  | status/cancel: target run_id (omitted for status = list all registered runs) |
| `spec` | object |  | run: inline suite spec object. Steps are a discriminated union (the type field decides the shape): input (method+params, native bridge params), wait (polls wait_for_node/wait_for_property), wait_frames (deterministic 1-60 frame advance), freeze/unfreeze, step_until (structured conditions {path,property,op,value}[], avoids RCE), snapshot/restore, set (write node properties), call (bridge read-only whitelist; write methods need GODOT_MCP_BRIDGE_EXTRA_METHODS), watch_start (node_path+signal_name, one watch per suite), watch_stop, monitor_start (node_path+properties[], one monitor per suite), monitor_stop, screenshot (evidence saved to the report directory), sleep. Give steps a label so diffs line up |
| `spec_path` | string |  | run: spec file path (.json, or .md with a ```qa-spec fence); use a file for big suites to avoid token truncation; must be inside the ALLOWED_PROJECT_PATHS whitelist |
| `project_path` | string |  | run: project path (overrides project_path in the spec; required if the spec has none) |
| `report_path` | string |  | report: report path or run_id; latest = newest, prev = second newest |
| `base_path` | string |  | diff: baseline report (default prev) |
| `head_path` | string |  | diff: report to compare (default latest) |
